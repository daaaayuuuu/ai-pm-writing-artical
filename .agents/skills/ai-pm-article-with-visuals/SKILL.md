# AI 产品文章与配图

把文章和视觉当成同一个内容产品推进。先通过短轮次对话确认方向，再写稿；先确定每张图要解释什么，再生成图片。不要把配图当成正文完成后的装饰。

## 每次先读取规则

- 始终读取 `references/writing-workflow.md`，执行选题、结构、研究、写作和平台适配。
- 涉及配图、封面、图表规划或图片修改时，读取 `references/visual-workflow.md`。
- 交付成稿或图片前，读取 `references/quality-checklists.md`。
- 默认用 `assets/style-reference-cover.png` 和 `assets/style-reference-body.png` 作为视觉参考；用户提供新参考时，以用户参考为准。
- 需要生成或编辑位图时，加载并遵守 `imagegen` Skill。需要精确文字、箭头和结构关系时，优先使用 SVG、HTML/CSS、Canvas 或确定性绘图方式。

## 选择工作模式

根据用户当前进度进入最靠后的可执行阶段，不重复已经确认的信息。

### 探索模式

用户只有材料或模糊想法时，按“材料理解 → 选题 → 标题 → 核心判断 → 结构 → 写作约束”推进。每轮最多问三个高价值问题，并等待用户回答后再进入下一阶段。

### 直接成稿模式

用户已确认题目，或明确说“开始写文章”时，保留所有已确认条件，只追问会实质改变文章的缺失信息。低风险缺失项使用推荐默认值，不把用户拉回前面的流程。

### 配图模式

用户已有文章或指定段落时，先提炼该段唯一要表达的关系，再给出图片用途、放置位置、结构和精确文案。用户要求直接生成时，不额外阻塞；否则先给配图方案等待确认。

### 精修模式

用户上传带红框、箭头或批注的图片时，把标注当作修改说明，不把标注带进成图。优先编辑无标注原图；锁定未被要求修改的文字、位置、颜色、比例和背景。一次只执行用户指出的变化。

## 对话控制规则

1. 复用用户已给出的平台、读者、字数、语气、经历和标题，不重复提问。
2. 选项使用 `A / B / C`，每项只解释关键取舍，并明确推荐项。
3. 用户说“跳过”时，采用最稳妥默认值继续，不再追问同一问题。
4. 用户说“先不要生成文章”时，只推进选题、标题、判断和结构。
5. 用户说“开始写”时，不再展示内部材料清单或隐藏提纲，直接交付正文。
6. 多篇笔记默认合并成一篇有中心判断的文章，不自动拆成系列。
7. 默认以正在学习和实践的 AI 产品经理身份写作，不强行从设计师视角切入；只有用户明确要求时才使用原职业视角。

## 阶段闸门

除非用户要求跳过，依次完成以下确认。

1. **材料与目标**：理解材料、发布平台、目标读者和文章用途。
2. **选题**：给出三至五个角度，说明中心问题、读者价值、证据基础和夸大风险。
3. **标题**：围绕用户选定角度提供标题，等待用户确认最终标题。
4. **核心判断与结构**：用一句话说明文章要证明什么，再给完整的章节关系。
5. **写作约束**：确认字数上限、语气、来源呈现方式和是否需要双平台通用稿。
6. **成稿**：研究、写作、审稿并输出可发布 Markdown。
7. **配图地图**：逐图确认“放在哪、解释什么、画什么、写什么”。
8. **生成与精修**：生成封面和正文图，检查后按用户标注做单点修改。
9. **发布包**：交付文章、图片和明确的插图位置表。

## 写作底线

- 先确定一个中心问题和一个作者愿意负责的判断，再组织标题与章节。
- 把个人体验、公开事实、合理推断和产品判断分开表达。
- 个人体验不是严格评测；没有同任务对照、样本和指标时，不写成普遍结论。
- 涉及当前产品、模型、版本、价格、技术机制和公司信息时，先查最新一手资料；技术事实优先使用官方文档、代码仓库、论文和公告。
- 即使用户要求去掉“关键来源”，仍需完成事实核验；只是不在发布稿中单列来源区。
- 面向新人解释术语时，第一次出现给出一句普通话定义，并说明它在真实产品流程中的位置。
- 正文使用短段落、编号一级标题和清楚的因果关系。不要用行业大势、宏大叙事、空泛金句或堆叠黑话填充篇幅。
- 微信公众号强调移动端节奏和个人判断；“人人都是产品经理”强调问题定义、机制、边界和可执行方法。默认先写一篇两边都能用的核心稿。

## 配图底线

- 每张图只回答一个问题，必须能指向正文中的一个具体段落或结论。
- 默认配图预算为一张封面加四张正文图；文章开头存在强核心判断时，可以增加一张开篇判断图。
- 先画关系，再选形式：层级用层级图，循环用 Loop，扩展生态用中心辐射，成本机制用因果图，精确对比用表格或卡片。
- 图中只保留读者理解关系所需的文字，不把整段正文搬进图片。
- 图中文字必须逐字校验；箭头起点、终点、方向和线条对齐必须检查。
- 默认封面尺寸为 `2048×872`，正文图为 `2048×1280`。移动端优先，大标题和关键卡片在缩小后仍需清楚。
- 默认去掉封面顶部标签；标题层级相同的词保持相同字号、颜色和字重，只有作者明确要强调的部分使用亮蓝色。
- 保存修改版时使用版本号，不覆盖旧图，除非用户明确要求替换。

## 交付要求

默认交付以下内容：

1. 可发布的 Markdown 正文。
2. 文章封面与正文配图文件。
3. 配图位置表，精确到“放在某一段或某一句之后”。
4. 必要的平台排版说明。

长文完成后运行：

以当前 `SKILL.md` 所在目录为基准运行：

```bash
python3 <Skill目录>/scripts/validate_article_package.py <文章.md> --max-chars <字数上限> --expect-images <图片数> --strict-dimensions
```

根据检查结果人工修正，不让脚本替代编辑判断。只向用户报告重要的修改结果和最终文件，不展示内部检查过程。
